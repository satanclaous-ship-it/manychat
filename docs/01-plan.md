# auto-dm 기획서 — 매니챗 클론 v1 (문서 1/3)

> 목적: 이 문서 3종(기획서·설계서·빌드 가이드)만 가지고 오푸스 빌드 세션을 돌려,
> 내 인스타그램 계정에서 댓글 자동 DM이 실제로 작동하게 한다.
> 코드 레포: `satanclaous-ship-it/auto-dm` / 문서 원본: 이 레포 `outputs/`

## 1. 목적과 배경

- 매니챗(ManyChat)의 월 구독 비용을 내는 대신, 당장 필요한 기능을 직접 만들어 **월 고정비 0원**으로 운영한다.
- 당장 쓰고 싶은 기능 = **댓글 단 사람에게 자동으로 DM 보내기**. 나머지 매니챗 기능은 확장 가능한 뼈대 위에 하나씩 얹는다.
- 파일럿 프레임: 완벽한 매니챗 복제가 아니라, **내 계정 하나에서 실제로 돌아가는 것**이 v1의 성공이다. 남에게 서비스하는 SaaS가 아니다.
- 첫 실전 사용처: **'3주 빛' 무료 e북 배포** — 상품 사다리의 입구(콘텐츠 → e북=연락처 교환)를 자동화한다. 게시물에 키워드 댓글을 단 사람에게 e북 링크를 DM으로 흘려보낸다.

## 2. 매니챗 기능 지도 vs v1 범위

| 매니챗 기능 | v1 | 사유 |
|---|---|---|
| 댓글 → 자동 DM (Comments Growth Tool) | ✅ 포함 | 당장 쓰고 싶은 핵심. 첫 가동 대상 |
| DM 키워드 자동응답 | ✅ 포함 | 같은 트리거 엔진으로 처리 가능 |
| 스토리 답장·멘션 반응 | ✅ 포함 | 웹훅 이벤트만 다르고 구조 동일 |
| 시퀀스 (응답 후 시간차 후속 발송) | ✅ 포함 | 24시간 윈도우 안에서만 (§5 제약) |
| 라이브 챗 인박스 | ✅ 포함 (간소화) | 대화 내역 보기 + 수동 개입. 배정/팀 기능 없음 |
| 연락처 관리 (태그) | ✅ 포함 (간소화) | 사람별 태그·이력. 커스텀 필드/세그먼트는 태그로 대체 |
| 대화 플로우 (버튼 다단계) | ❌ 제외 | 인터뷰에서 제외 확정. 트리거 엔진 위에 v2로 증축 가능 |
| 비주얼 플로우 빌더 | ❌ 제외 | 폼 기반 대시보드로 충분. 빌드 분량 2~3배 사유 |
| 브로드캐스트 (전체 발송) | ❌ 제외 | 24시간 윈도우 밖 대량 발송은 정책 제약이 크고, 단일 계정 개인용에선 가치 낮음 |
| 인스타 외 채널 (FB·WhatsApp·SMS·텔레그램) | ❌ 제외 | 인스타그램 전용 |
| AI 자동응답 | ❌ 제외 | v1은 결정적(deterministic) 규칙만 |
| 성장 도구 (랜딩페이지·QR) | ❌ 제외 | 불필요 |

**단일 계정 전용** (확정): 내 프로페셔널 계정 1개만. Meta 앱 심사 없이 개발 모드로 운영한다 — 앱에 역할이 있는 본인 계정에는 모든 기능이 작동한다. 나중에 남에게 서비스하려면 그때 앱 심사 + 멀티테넌트 확장.

## 3. 핵심 유스케이스 시나리오

### UC1 — 댓글 → e북 DM (첫 실전 가동)
1. 게시물(캐러셀/릴스)에 안내: "'빛'이라고 댓글 달면 e북을 DM으로 보내드려요"
2. 누군가 댓글에 "빛" 포함 문구 작성
3. 시스템이 웹훅으로 댓글 수신 → 규칙 매칭 (게시물 ID + 키워드)
4. 액션 실행:
   - (선택) 댓글에 공개 답장: "DM 보냈어요 🌊"
   - 비공개 답장(private reply)으로 e북 링크 DM 발송
   - 연락처에 태그 부착: `ebook-3light`
5. 같은 사람이 같은 게시물에 다시 댓글 → **재발송하지 않는다** (1인 1회 규칙)
6. (시퀀스 — 조건부) **상대가 그 e북 DM에 답장을 보내 24h 윈도우가 열린 경우에만**, 그로부터 10분 뒤: "잘 받으셨나요? 읽다가 궁금한 게 생기면 편하게 답장 주세요 🪨"
   ⚠️ **정책상 한계**: 댓글만 단 사람은 아직 대화 윈도우를 열지 않았다(§5.1 — 댓글은 윈도우 안 염, private reply는 1회 진입로일 뿐). 그래서 댓글 트리거의 후속 발송은 상대가 답장하기 전까지 발송되지 않고 `expired` 처리된다. 후속 발송을 확실히 쓰려면 DM 키워드 트리거(UC2, 인바운드 DM이 윈도우를 엶)에 붙이는 게 맞다.

### UC2 — DM 키워드 자동응답
1. 누군가 내 계정에 "e북"이라고 DM
2. 웹훅으로 메시지 수신 → 키워드 규칙 매칭
3. e북 링크 자동 응답 + 태그 부착
4. 내가 보낸 메시지(echo)는 트리거로 취급하지 않는다

### UC3 — 스토리 답장 반응
1. 내 스토리에 누군가 답장 (이모지/텍스트)
2. 웹훅 수신 → 스토리 답장 규칙 매칭 (키워드 조건 선택 가능, "모든 답장" 옵션)
3. 감사 메시지 자동 응답 (예: 오늘의 리소스 링크)
4. 스토리 답장은 24시간 윈도우를 여는 사용자 액션이므로 자유롭게 응답 가능

## 4. 기능 정의 — 시퀀스·인박스·연락처

### 시퀀스 (후속 발송)
- 자동화 규칙에 "n분/시간 뒤 후속 메시지" 단계를 0~3개 부착할 수 있다.
- 후속 메시지는 **마지막 수신 인바운드로부터 24시간 이내**만 발송된다 (§5). 윈도우를 넘긴 예약분은 발송하지 않고 `expired`로 기록한다.
- 상대가 그 사이에 새 메시지를 보내면 윈도우가 갱신되어 발송 가능 시간이 늘어난다.
- 예약 취소 조건: 상대가 먼저 같은 내용을 물어봐서 수동 개입한 경우, 인박스에서 예약 취소 가능.

### 인박스
- 대화 목록: 최근 메시지 순, 자동/수동 발송 구분 표시.
- 대화 상세: 주고받은 메시지 타임라인 + 이 사람에게 발동된 자동화 이력.
- 수동 발송: 24시간 윈도우 안이면 대시보드에서 직접 답장 가능. 윈도우 밖이면 발송 버튼 비활성 + 사유 표시.
- 자동화 일시정지: 특정 대화에서 자동응답 끄기 (수동 상담 중 충돌 방지).

### 연락처
- DM/댓글로 접점이 생긴 사람이 자동 등록: 인스타 유저 ID, 유저네임, 최초/최근 접점.
- 태그: 자동화가 부착하거나 수동 부착. 예: `ebook-3light`, `week2-참가자`.
- 목록에서 태그 필터 → e북 받은 사람 명단으로 활용 (사다리 다음 단계 제안의 기반).
- 내보내기: CSV 다운로드 (연락처+태그) — 리드 명단을 레포 밖 도구에서도 쓸 수 있게.

## 5. Meta 정책 제약 (설계가 지켜야 하는 선)

> 아래 수치·규칙은 2026-07 기준 공식 문서 검증 결과다. 상세 출처는 설계서 §10 부록 참조.

1. **24시간 메시징 윈도우**: 상대의 인바운드 메시지(DM, 스토리 답장 — 댓글은 해당 안 됨)로 대화 윈도우가 열리고, 마지막 인바운드 기준 **24시간 안에만** 자유 형식 메시지를 보낼 수 있다. 시퀀스는 이 안에서만 동작한다. 윈도우를 7일로 늘리는 HUMAN_AGENT 태그는 앱 심사 필수 + **자동화 발송 금지**(사람 상담원 전용)라 v1에서 쓰지 않는다.
2. **Private reply (댓글 → 비공개 DM)**: 댓글에 대한 비공개 답장은 **댓글 1건당 1회만** 보낼 수 있고, 라이브 방송 중 댓글이 아닌 일반 댓글은 **댓글 생성 후 7일 이내**에 보내야 한다. 이 1회 DM은 24시간 윈도우와 별개로 허용되는 진입점이다. 상대가 그 DM에 답하면 그때 24시간 윈도우가 열린다.
3. **개발 모드 운영**: 앱을 라이브 전환하지 않고 개발 모드로 두면, 앱 역할(관리자/테스터)이 있는 계정 — 즉 내 계정 — 에만 작동한다. 단일 계정 전용이므로 **앱 심사 불필요**. 단, 타인 계정에는 절대 동작하지 않는다는 것이 제약이자 안전장치다. *(웹훅은 개발 모드에서도 앱 역할 보유 계정 이벤트는 수신된다 — 빌드 가이드 M1에서 실측 확인을 첫 판정 기준으로 둔다.)*
4. **자동응답 정체 고지**: 자동화된 경험임을 상대가 알 수 있게 한다 — 첫 자동 DM에 봇임을 가볍게 밝히는 문구를 기본 템플릿에 포함 (예: "(자동으로 보내드리는 메시지예요)").
5. **요율 제한**: 텍스트 메시지 기준 계정당 초당 100건 — 개인 규모에서 유의미한 한도 없음 (업계에 도는 "시간당 200 DM" 류 수치는 공식 한도가 아니므로 인용하지 않는다). 만일의 429 응답은 재시도 큐로 처리 (설계서 §4.6).
6. **금지 영역**: 윈도우 밖 마케팅 대량 발송(브로드캐스트)은 v1 범위 밖 — 정책상 승인된 메시지 태그가 필요한 영역이라 제외했다.

## 6. 성공 기준 — 무엇이 되면 "가동"인가

1. 내 게시물에 테스트 댓글(키워드 포함)을 달면 **60초 안에** 내 다른 테스트 동선으로 e북 링크 DM이 도착한다.
2. 대시보드(폰 브라우저)에서 자동화 규칙을 새로 만들고/끄고/키워드를 바꿀 수 있다 — 코드 수정 없이.
3. 시퀀스 후속 메시지 1건이 예약 시각(±1분)에 발송된 기록을 확인한다.
4. 인박스에서 해당 대화가 보이고, 수동 답장이 실제 DM으로 전달된다.
5. 연락처에 태그 `ebook-3light`가 자동 부착되어 있고, 태그 필터로 명단을 뽑을 수 있다.
6. 한 달 운영 비용 0원 — Cloudflare 대시보드에서 무료 한도 사용률 확인 (예상: 한도의 1% 미만).

가동 판정일에 매니챗 구독 대체 여부를 결정한다 — 이 문서 세트의 목표.

## 부록 — 스펙 (이 문서 세트의 완성 기준)

- **목표**: 이 가이드 문서 세트만 가지고 오푸스 빌드 세션을 돌려, 내 인스타 계정에서 댓글 자동 DM이 실제로 작동하기 시작한다.
- **독자와 쓰임**: ① 사용자 본인(설계 검토 + Meta 콘솔 손작업) ② auto-dm 레포의 오푸스 빌드 세션(구현 스펙).
- **완성 기준**:
  1. 가이드만 보고 외부 검색 없이 Meta 앱 설정 → 배포 → 첫 자동 DM까지 도달 가능
  2. 기능 3묶음(트리거·자동DM / 시퀀스 / 인박스·연락처)의 데이터 모델·이벤트 흐름·화면 정의 완비
  3. 마일스톤별 오푸스 킥오프 프롬프트 + 측정 가능한 완료 판정 기준
  4. Meta 정책 제약 명시 + 위반 설계 0건
  5. 월 고정비 0원 구조를 수치로 확인
- **범위 밖**: 대화 플로우(버튼 다단계), 비주얼 플로우 빌더, 브로드캐스트, 타 채널, 멀티테넌트 SaaS, AI 자동응답
- **핵심 결정 (사용자 확정 ✅)**: 목표=실작동 / 기능 3묶음(플로우 제외) / 웹훅+Cloudflare Workers 무료 / 심플 웹 대시보드 / 코드는 새 레포 auto-dm·문서는 허브 outputs/ / 첫 사용처='3주 빛' e북 배포 / 단일 계정 전용 / 문서 3분할·단계별 제작
- **잔여 리스크 (⚠️ 실측 필요)**: 개발 모드에서 타인 댓글/DM 이벤트 수신 여부 — 빌드 가이드 M1 판정 기준이 실측 관문. 미수신 시 런북 R-5(심사 경로).
